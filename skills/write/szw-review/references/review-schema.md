# 05-review.md / Review commit Schema

> `/szw-review commit` 通过 stdin 接收的 JSON 字段契约 + 渲染到 `articles/<slug>/05-review.md` 的结构 + style-profile 累积逻辑。
> 修改本文档须同步更新 `scripts/finalize-review.py` 的 `REQUIRED_*_FIELDS / VALID_*` 集合 + render / append 逻辑。

---

## stdin JSON top fields

| 字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `phase1` | dict | ✅ | Phase 1（skeptical review）产物 |
| `phase2` | dict | ✅ | Phase 2（style capture）产物或 skip 标记 |
| `verdict` | enum | ✅ | `review_passed` / `review_failed` |
| `notes` | str | ⛔ | 整体说明 |

### `phase1` 字段

| 子字段 | 类型 | 必需 | 说明 |
|---|---|---|---|
| `loop_rounds` | int | ✅ | Phase 1 内部循环次数（0/1/2）；非负 |
| `issues` | list[Issue] | ✅ | 可空数组（无问题就 review_passed） |
| `summary` | str | ⛔ | 整体说明 |

### `Issue` 项

| 字段 | 类型 | 必需 | 取值 |
|---|---|---|---|
| `id` | str | ✅ | 自由 ID（如 I1 / H1 / M2） |
| `severity` | enum | ✅ | `HIGH` / `MEDIUM` / `LOW` |
| `category` | enum | ✅ | `fact` / `counterargument` / `boundary` / `style` / `claim` |
| `location` | str | ✅ | `S2 §3 paragraph 2` 或 `overall` 等；含 S\<n\> 时 next_action 自动定位 |
| `description` | str | ✅ | 问题描述 |
| `evidence` | str | ⛔ | 反驳依据；可空 |
| `suggestion` | str | ✅ | 修复建议 |

### `phase2` 字段

```json
{
  "skipped": true | false,
  "skip_reason": "diff < threshold" | "style_capture.enabled=false" | "no snapshot" | ...,
  "diff_pct": 12.5,                         // 仅 not skipped 时有
  "snapshot_compared": "01-both-full-2026-05-06T10-15.md",   // 仅 not skipped
  "features": {                             // 仅 not skipped 时必有
    "vocabulary_substitutions": [
      {"ai_pref": "或许", "author_pref": "(deleted)", "frequency": 3, "examples": ["..."]}
    ],
    "sentence_patterns": [
      {"pattern": "不是 X 而是 Y", "frequency": 5, "examples": ["..."]}
    ],
    "rhythm_paragraph": ["short sentences preferred"],
    "punctuation_mixing": ["—— preferred over --"],
    "anti_patterns": ["在某种程度上", "三段并列"]
  }
}
```

`features` 5 类（任意子类可空数组；但全空且 not skipped 时无需写 style-profile，脚本自动跳过 append）：

- `vocabulary_substitutions`: list of `{ai_pref, author_pref, frequency, examples?}`
- `sentence_patterns`: list of `{pattern, frequency, examples?}`
- `rhythm_paragraph`: list of str（自由短语）
- `punctuation_mixing`: list of str
- `anti_patterns`: list of str（作者反复删除的词/句）

## verdict gate

| verdict | HIGH issues | 行为 |
|---|---|---|
| `review_passed` | 0 | ✅ commit |
| `review_passed` | ≥ 1 | ❌ exit 5（自相矛盾） |
| `review_failed` | (任意) | ✅ commit；ARTICLE.md status → review_failed |

`review_failed` 即使无 HIGH 也允许（用户可基于 MEDIUM 决定 fail；脚本不强制）。

---

## 状态推进 + next_action

| verdict | new_status | next_action 规则 |
|---|---|---|
| `review_passed` | `review_passed` | `/szw-publish <slug>` |
| `review_failed` | `review_failed` | 找第一个 HIGH issue 的 `location`：含 `S<n>` → `/szw-write <slug> S<n> --mode polish`；否则 → `/szw-write <slug> --mode polish` |

`location` 字段写得越准（如 `"S2 §3 paragraph 2"`），next_action 就能精确指向某节修复。

### 首次创建（不存在时）

```markdown
# Author Style Profile

> Auto-generated by `/szw-review` Phase 2; consumed by `/szw-write` Phase 1+2.
> Last updated: <date>; sample size: 1 article, N edit instance(s).

## Stable Patterns（频次 ≥ 3，已合并）

### Vocabulary Substitutions
| AI 倾向 | 作者偏好 | 频次 | 来源 |
|---|---|---|---|

### Sentence / Rhythm
_(待累积)_

### Anti-Patterns（用户反复删除）
_(待累积)_

## Recent Edits（待合并的增量，每次 review 追加）

| 日期 | Article | Category | Detail |
|---|---|---|---|
| <date> | <slug> | vocab | AI 用 `X` → 作者 `Y` (freq=N) |
...
```

### 追加（已存在时）

- 更新 meta blockquote：`Last updated` 替换为今天；`sample size: X articles, Y edit instances` 累加（X+1, Y+n_added）
- `## Recent Edits` 表末尾追加新行（每条 feature 一行）

### Recent Edits 行格式

| Category | Detail 模板 |
|---|---|
| `vocab` | `AI 用 \`<ai>\` → 作者 \`<author>\` (freq=N)` |
| `sentence` | `偏好 \`<pattern>\` (freq=N)` |
| `rhythm` | 自由短语 |
| `punctuation` | 自由短语 |
| `anti-pattern` | `删除 \`<pattern>\`` |

### 自动合并（v3.0 deferred）

`style_capture.merge_after_n_reviews`（默认 10）：累计 ≥ N 次 review 后，自动合并 `## Recent Edits` 到 `## Stable Patterns`，按 `style_capture.min_pattern_frequency`（默认 3）过滤。

**当前实现仅做 append**；自动合并由未来 `/szw-cleanup` 或 `/szw-review --merge-style` 触发。
