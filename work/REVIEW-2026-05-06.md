## 3. 一致性问题（需修复）

按严重度排序：

### 🔴 P0-1：fan.md ↔ EDITORIAL_CONTEXT.md 模板的 §X 编号严重不匹配

**问题**：fan.md 多处引用 EDITORIAL_CONTEXT 的虚构节号：

| fan.md 引用 | 实际模板 | 实际是 |
|---|---|---|
| §6 Article Types（fan.md §3.2 / §3.3） | §6 实际 | "Argument Standards" |
| §10 Evidence Standards（fan.md §4.2） | 不存在 | 模板最高 §7 |
| §11 Style Guide（fan.md §3.4 Phase 1） | 实际 §7 | "Style Guide" |
| §11 / §12 banned patterns（fan.md §3.4 Phase 2） | 不存在 | 在 §7 Style Guide 内 |
| §15 Chinese Writing Preferences（fan.md §3.4 Phase 2） | 不存在 | — |

**SKILL.md 引用现状**：
- ✅ szw-discuss / szw-write / szw-review 已经按模板实际节号引用（§3 / §5 / §7）
- ❌ szw-research/SKILL.md:54 仍按 fan.md 引用 "§10 Evidence Standards"

**修复方向（三选一）**：
1. **扩展 EDITORIAL_CONTEXT.md 模板**到 §15，加上 Article Types / Evidence Standards / Banned Patterns / Chinese Writing Preferences 节
2. **改 fan.md** §X 编号匹配实际模板
3. **维持现状 + 改 szw-research/SKILL.md** 改成 §3-§7 实际节号或"如有此节"措辞

**推荐方向 1**：扩展模板。原因：
- fan.md 设计意图清楚（这些节都是有用的）
- 模板补这几节让 EDITORIAL_CONTEXT 真正承载"写作宪法"的全套内容
- skill 引用稳定下来

### 🔴 P0-2：next_action 字串带 slug 不一致

**问题**：finalize-* 写入 STATE.md 的 next_action 列：

| skill | next_action 格式 | 是否带 slug |
|---|---|---|
| new-article | `/szw-discuss` | ❌ 不带 |
| discuss | `/szw-write` | ❌ 不带 |
| research | `/szw-outline` | ❌ 不带 |
| outline | `/szw-write` | ❌ 不带 |
| write | `/szw-review` | ❌ 不带 |
| **review** | `/szw-publish <slug>` 或 `/szw-write <slug> S<n> --mode polish` | ✅ 带 |

review 是 outlier。**5 处不带 slug，1 处带**。

**修复**：统一带 slug（review 已对，改前 5 处）。原因：
- 多 article 场景下 next_action 应可直接 copy-paste 执行
- 不带 slug 的命令依赖"current"语义（隐含取最新），易混淆

**修复点**：
- `szw-new-article/scripts/new-article.py` 的 `new_row` 模板
- `szw-discuss/scripts/finalize-discuss.py` 的 `update_active_row(... new_next_action="/szw-write")` → 改 `f"/szw-write {slug}"`
- `szw-research/scripts/finalize-research.py` 同
- `szw-outline/scripts/finalize-outline.py` 同
- `szw-write/scripts/finalize-write.py` 的 `state_next_action` 同

### 🟡 P1-1：`find_active_section_bounds` 签名不一致

**问题**：

| skill | 返回签名 |
|---|---|
| **szw-discuss** | `tuple[int, int, int, int]` (section_start, section_end, sep_idx, data_start) |
| szw-outline / szw-research / szw-review / szw-write | `tuple[int, int, int]` (section_end, sep_idx, data_start) |

szw-discuss 多带一个 `section_start`，但函数体内未实际使用。

**修复**：把 szw-discuss 的版本改成 3-tuple 对齐其他。

### 🟡 P1-2：`update_article_frontmatter` 签名分歧

3 种变体：

| 变体 | skill | 签名 |
|---|---|---|
| **重载版** | szw-discuss | `(path, new_status, today, new_thesis=None, new_target_platforms=None, extra_log=None)` |
| 标准版 | szw-outline / szw-research / szw-review | `(path, new_status, today, extra_log)` |
| 可空 status | szw-write | `(path, new_status: str \| None, today, extra_log)` |

**评价**：
- szw-discuss 的"重载版"是首个实现，多了 thesis 替换 + target_platforms 替换的特殊能力（仅本身用到）
- szw-write 的"可空 status"是 polish 模式不动 status 的合理需求
- 不是 bug，但同名函数 3 种签名不利维护

**修复方向**：
- 把 szw-discuss 拆成两个：`update_article_status_and_log()` + `replace_thesis_and_platforms()`
- 把 szw-write 的可空 status 也对齐到其他（或者其他都加 `| None`）

**建议**：低优先级，等下次重构时一起处理。

### 🟡 P1-3：szw-write 对 style-profile.md 的态度弱化

**fan.md §3.4 Phase 1 step 1**：
> 加载 outline + ... + **style-profile.md（作者风格档案）**

把 style-profile.md 列为 mandatory 加载项（与 outline 并列）。

**szw-write/SKILL.md 当前措辞**：
- Phase 0: `style_profile` ... "可能 null"
- Phase 1: "**必读** style-profile.md（如果存在）"

**评价**：技术上正确（首次起稿时 style-profile 不存在，确实只能 if-exists）。但措辞偏弱，没有强调"如果存在则必读且必须主动应用 anti-patterns"。

**修复**：SKILL.md Phase 1 增强措辞，明确：
- 存在 → 必读 + 强约束 anti-patterns 必避 + 强偏好 vocabulary substitutions
- 不存在 → 跳过（首次起稿合理）

修改成本：仅改 SKILL.md 文字。

### 🟢 P2-1：fan.md 自身的 §15 Chinese Writing Preferences 不存在

fan.md §3.4 Phase 2 step 8 引用 "§15 Chinese Writing Preferences"，但 fan.md §15 实际是别的（决策原因 meta 节）。

**修复**：fan.md 中改成"在 EDITORIAL_CONTEXT.md 增加中文偏好节"或删除此引用。

- 退出码：0 / 1 / 2 / 3 / 4 / 5

**关键复用**：
- `remove_from_active_and_add_to_completed()` —— **直接拷贝** szw-discuss/finalize-discuss.py 的同名函数（已实现 + 测试通过）

**实现复杂度**：低（大量复用已有逻辑）。
